# Next.js Patterns

## Overview

Patterns and conventions for Next.js 14+ App Router projects. All guidance assumes TypeScript strict mode, `pnpm`, and Turbopack as the default bundler.

## Behavior

### Package Manager
- Always use `pnpm` — never `npm` or `yarn` in commands.
- `pnpm --filter=next build` for the Next.js package; `pnpm build` for the full workspace.
- `pnpm --filter=next dev` for watch mode (~1–2s rebuilds vs ~60s full build).

### Bundler
- Turbopack is the default for `next dev` and `next build`.
- Force webpack only when explicitly needed: `next build --webpack`.
- No `--no-turbopack` flag — it does not exist.

### App Router conventions
- `app/` directory only. Do not create files under `pages/`.
- Server Components are the default. Add `"use client"` only when:
  - Component uses `useState`, `useEffect`, or browser-only APIs.
  - Component attaches event listeners.
- Pass data via props or `fetch()` in Server Components — do not lift server data into client state.
- Route handlers: `app/api/<name>/route.ts` — export `GET`, `POST`, etc. as named functions.
- Metadata: export `metadata` or `generateMetadata` from `page.tsx`, never from `layout.tsx` (unless shared).

### Feature Flags
- Type definition: `next.config.ts` → `experimental` block.
- Schema: `config-schema.ts` (Zod or similar).
- Runtime env: `define-env.ts` — force edge-incompatible flags to `false` for edge builds.
- Keep `require()` behind compile-time `if/else` branches for DCE — avoid early-return/throw patterns that prevent tree-shaking.

### Testing
- Generate test suites with `pnpm new-test` (creates proper fixture structure).
- Use `retry()` from `next-test-utils` for async waits — never `setTimeout`.
- Mode-specific scripts: `pnpm test-dev-turbo`, `pnpm test-dev-webpack`, `pnpm test-start-turbo`.
- Never re-run the same test with different filters mid-session — capture output to file, then analyze.

### PR / Git conventions
- Every PR description opened by an LLM **must include** the HTML comment: `<!-- NEXT_JS_LLM_PR -->`
- Leave PRs in **draft** state — do NOT mark ready for review. That decision belongs to the human.
- Do NOT add `Generated with Claude Code` or `Co-Authored-By` footers to commits or PRs.
- Commit messages: concise, imperative, describe the why not just the what.

### Deployment (Vercel)
- Environment variables: separate sets for preview, production. Never commit secrets.
- Edge Runtime: only use when response time is critical — it has limited Node.js API access.
- `vercel.json` for redirects/rewrites; prefer `next.config.ts` for everything else.
- Image optimization: always use `next/image`. Never raw `<img>` tags.
- Font optimization: always use `next/font`. Never manually load Google Fonts via `<link>`.

## Rules

- MUST use `pnpm` for all package management commands.
- MUST default to Server Components; add `"use client"` only when proven necessary.
- MUST include `<!-- NEXT_JS_LLM_PR -->` in every PR description.
- MUST leave PRs in draft.
- MUST NOT add co-author or "generated by AI" footers to commits.
- MUST NOT use `pages/` directory for new routes.
- MUST NOT use raw `<img>` or `<link>` for Google Fonts.
- MUST use `retry()` not `setTimeout` in tests.

## Examples

**Correct Server Component data fetch:**
```tsx
// app/dashboard/page.tsx — Server Component (no "use client")
export default async function DashboardPage() {
  const data = await fetch('https://api.example.com/stats', { next: { revalidate: 60 } });
  const stats = await data.json();
  return <StatsGrid stats={stats} />;
}
```

**Correct route handler:**
```ts
// app/api/users/route.ts
export async function GET(request: Request) {
  const users = await db.user.findMany();
  return Response.json(users);
}
```

**PR description (LLM-authored):**
```markdown
## Summary
- Add real-time notifications via Supabase Realtime
- New hook: `useNotifications`

<!-- NEXT_JS_LLM_PR -->
```
