## Development Rules

### Supabase client usage
- **Server Components, Route Handlers, Server Actions**: use `createServerClient` from `@supabase/ssr` (imported from `lib/supabase/server.ts`).
- **Client Components**: use `createBrowserClient` from `@supabase/ssr` (imported from `lib/supabase/client.ts`).
- **Never** use the legacy `@supabase/auth-helpers-nextjs` — it is deprecated.
- **Never** use `service_role` key in client-side code. It bypasses RLS and is a critical security issue.

### Row Level Security (RLS)
- RLS must be enabled on every table that contains user data.
- Never disable RLS to "make something work faster" — fix the policy instead.
- Policies live in migrations, not applied ad-hoc via the dashboard.
- Test policies locally: `supabase db reset` + seed + verify queries as specific roles.

### Database migrations
- All schema changes go through migration files in `supabase/migrations/`.
- **Never** alter the production schema directly via the Supabase dashboard.
- Migration naming: `YYYYMMDDHHMMSS_description.sql` (auto-generated by `supabase migration new`).
- After schema changes: always regenerate types with `supabase gen types typescript --local`.
- `lib/database.types.ts` is auto-generated — never edit manually. Add a comment to catch accidental edits.

### Auth
- Use Supabase Auth for all authentication. Do not implement custom JWT.
- Session is refreshed via Next.js middleware (`middleware.ts`) on every request.
- Protected routes: check `supabase.auth.getUser()` in Server Components, not `getSession()` (getSession does not validate the JWT).

### Realtime
- Use Supabase Realtime for live data. Subscribe in Client Components with `useEffect`; unsubscribe on cleanup.
- Channel names: `<table>:<row-id>` or `<table>:all` for table-level subscriptions.

## Git & PR Conventions

- Branch names: `feat/<slug>`, `fix/<slug>`, `chore/<slug>`
- Commits: Conventional Commits, imperative mood, ≤50 chars.
- LLM-authored PRs: must include `<!-- NEXT_JS_LLM_PR -->` in description body.
- PRs: always **draft** first.
- **No** `Co-Authored-By: Claude` footers.
- **Never** force-push to `main`. **Never** `--no-verify`.

Fragments OK. Short synonyms. Technical terms exact. Code blocks unchanged.

## Security

- `service_role` key: server-side only, never exposed to browser.
- User input sanitized before any DB query (ORM / parameterized only).
- RLS enabled and tested on every table with user data.
- Run `pnpm audit` before every deployment.
